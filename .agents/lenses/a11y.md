# Accessibility — condensed lens

This file is here because its gate fired on this repo at seed time. A lens that is
present applies — do not re-judge the gate while auditing.

Findings use the standard format, with `a11y` in the principle slot, and the same
severity anchors as `principles.md`:

`[a11y/<severity high|med|low>] <file:line> — <what> — <smallest fix>`

In authored UI markup, the element's semantics — not its styling or its handlers —
are what a keyboard and assistive technology can use. Greppable structure only; never
a WCAG conformance audit, and never anything that needs a rendered page.

## Spot it

- `<img` with no `alt` attribute at all — an empty `alt=""` is a decision, not a
  finding.
- A click handler on a non-interactive element (`<div onClick`) with no `role`, no
  `tabindex`, and no key handler.
- A form control with no name: no associated `<label>`, no `aria-label` — a
  placeholder is a hint, not a name.
- An `<a>` with no `href` doing a button's job; an icon-only button with no
  accessible name.

## Fix it

Smallest rung first: use the semantic element (`<button>`, real `<a href>`) → name
the thing (`alt`, `<label>`, `aria-label`) → ARIA only where a design system
genuinely prevents the semantic element.

## Do NOT apply when

- It would claim a conformance level — "WCAG AA" is a property of a rendered, tested
  page.
- It's color, contrast, focus order, or motion — those need a rendered page and a
  measurement.
- A design-system wrapper supplies the semantics internally — read the wrapper before
  flagging its call sites; flag the wrapper if the defect is in it.
- The markup is generated or third-party — flag only the template's own authored
  lines.

Overlap discipline: near-identical components are DRY, multi-purpose components are
SOLID, token duplication is atomic. This lens only earns findings those cannot name:
semantics missing from the markup itself.

Grep results are candidates. No finding without reading the markup and naming who is
shut out.
