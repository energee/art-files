# Label Lab improvement audit — 2026-09-05

Read-only audit of Label Lab (Tauri + React + TypeScript beer-label editor) at commit `35bac01` (origin/main, worktree `.agents/worktrees/audit-2026-09-05`), run through eight lenses — Over-engineering (ponytail), React, TypeScript, Performance, Accessibility, UX & copy, Security, Tests — and triaged against `.agents/AGENTS.md`, `.agents/principles.md`, `.agents/conventions.md`, `.agents/ledger.md`/`learnings.md`, and the two newest specs (`2026-09-04-master-as-layers-design.md`, `2026-08-27-master-variation-design.md`). The lenses produced 103 raw findings; after merging findings that name the same line or mechanism, dropping four that do not hold or duplicate the ledger, and spot-checking every high/med claim against the cited source, 81 backlog rows survive (several rows carry more than one raw finding). Severity follows `principles.md` anchors; Impact is user impact (high/med/low); Effort is S (under a couple of hours), M (half a day to a day), L (multi-day). "⚠ conflicts" marks a finding whose stated fix contradicts a governing doc, with the clause named. Nothing was changed; no fix was applied.

## Top ten

1. **Desktop cannot resolve a saved custom master (registration loop)** — `src/masters.ts:40` and `src/App.tsx:1720`. Impact: high. Effort: S. Why: `readMasterAt` reads `.master` paths through `readNativeFile`, but `src-tauri/capabilities/default.json:16` scopes `fs:allow-read-file` to `**/*.label` only (the comment at `src/files.ts:35` even says so), and under Tauri "Open Master…" falls to the hidden `<input>` and registers the master with a bare basename — so every `.label` saved against a non-shipped master reopens to "open its .master file once to register it" no matter how many times the user does exactly that. Fix: add a `**/*.[mM][aA][sS][tT][eE][rR]` read-scope entry, route Open Master through the dialog plugin's `open()` (add `dialog:allow-open`) so a real path is remembered, and surface the read error instead of swallowing it in `readMasterAt`'s catch. Lenses: ux (two findings, same job), security (read-scope finding, see #4 for the tension).
2. **"Check for Updates…" exists only in the macOS application menu** — `src/components/AppMenu.tsx:345` (comment: "non-macOS menus have no updater item"). Impact: high. Effort: S. Why: Windows/Linux users and the browser Menubar have no user-initiated update path, so an offline launch (silent check failure at `DesktopUpdater.tsx:145`) leaves no way to retry. Fix: add a `check-for-updates` action to `APP_MENUS` (e.g. a Help menu) so every platform's menu carries it. Lenses: ux.
3. **three.js ships in the entry chunk for a view most sessions never open** — `src/App.tsx:90` (static `CanView` import → `three/canScene`). Impact: high. Effort: S. Why: the 1.49 MB / 446 kB-gzip entry chunk parses all of three.js before first paint while the same-scale `@pdf-lib/fontkit` is already correctly code-split behind `import("@/pdf/build")`. Fix: `React.lazy`/`Suspense` (or a dynamic import gated on `viewMode === "3d"`) for `CanView`, applying the policy `pdf/build.ts` and `psd/build.ts` already follow. Lenses: performance (two findings).
4. **`masterHint` from an untrusted `.label` drives a native file read with extension-only containment** — `src/App.tsx:1441` → `src/masters.ts:38-45`, `src-tauri/capabilities/default.json:14-19`. Impact: high. Effort: M. Why: any shared `.label` can name an arbitrary path (including `../../…`) and the app reads it silently, with no directory containment — only a 5-character extension glob. Fix: keep the hint (the 2026-08-27 spec §Library index designs the fallback) but require it to resolve inside a known root (the opened label's directory or the registered masters directory) before reading, and scope the capability to those directories rather than a bare glob. ⚠ conflicts: the lens's "drop unauthenticated hints" variant contradicts spec §Library index ("a missing master falls back to `masterHint`, then a picker"); use the containment variant. Note the tension with #1, which needs the scope *widened* to `.master` — do both in one change. Lenses: security (two findings).
5. **No ESLint, so the 12 hand-written `eslint-disable-next-line react-hooks/exhaustive-deps` comments are unverified prose** — `package.json` (no eslint devDependency, no config, `.github/workflows/ci.yml` has no lint step). Impact: high (principles.md: an absent evidence base that should exist). Effort: M. Why: rules-of-hooks and exhaustive-deps are never enforced, so a conditional hook or stale closure in App/TabsShell/CanView/PreviewCompare/AppMenu has no automated catch. Fix: add eslint + `eslint-plugin-react-hooks` (+ jsx-a11y) with a `lint` script wired into CI. Lenses: react.
6. **A second, dead v1 authoring model is maintained beside the v3 one** — `src/model/document.ts:126`, `src/model/resolve.ts:29`, `src/model/lolev.ts:28`, `src/model/masterfile.ts:1`. Impact: med. Effort: M. Why: document.ts (736 lines) has one production importer, `convert.ts:25` pulling `configDiff`; resolve.ts, lolev.ts and masterfile.ts have zero src importers and are kept alive by nine test suites (~890 lines) that guard behaviour no user can reach, and three of the TypeScript lens's cast findings (`resolve.ts:107-110`, `:121`, `document.ts:588`) live only in this dead code. Fix: move `configDiff`/`diffValue` into `model/convert.ts`, delete the four files and the suites that exist only to exercise them (`model-document`, `model-authoring`, `model-resolve`, `model-master-layers`, `model-lolev`, `masterfile-zip`), inlining a minimal v1 fixture where the converter tests need one. Lenses: ponytail (four findings), typescript (three findings resolved by the deletion).
7. **`validateField` speaks a dead `FieldDecl` and returns a Result whose `error` is optional on failure** — `src/model/fields.ts:10-14`, callers `src/model/resolveLayers.ts:26-28,35-36`, `src/components/TextEditor.tsx:600`. Impact: med. Effort: S. Why: every v3 caller fabricates a `FieldDecl` with `path: ""` (the code says "ponytail: validateField still speaks FieldDecl"), only the number/code branches are reachable, and every caller has to write `r.error!` because `{ ok: boolean; error?: string }` never narrows. Fix: replace with `validateInput(input: "number" | "code", value, { min, max, symbology })` returning `{ ok: true } | { ok: false; error: string }` and delete the `!` assertions. (conventions.md §Error handling cites `{ ok, error? }` as the two-tier shape; the union keeps the return-not-throw convention.) Lenses: ponytail, typescript (three findings).
8. **`drawPlate` re-parses every SVG path into a fresh `Path2D` on every repaint** — `src/canvas/draw.ts:131`. Impact: med. Effort: S. Why: every keystroke repaints the plate (per the 2026-09-05 editor-performance ledger entry), and `r.paths.map((d) => new Path2D(d))` re-parses the identical laurel/logo path strings each frame even though `logo.ts`/`planLayers` return the same strings. Fix: cache `Path2D` objects keyed by path string (a `Map`/`WeakMap` beside logo.ts's cache) and reuse across paints. Lenses: performance.
9. **Export PDFs opens two unannounced OS save dialogs, blurs the preview with the wrong copy, and reports raw `String(err)`** — `src/App.tsx:1114` (two sequential `saveVia` calls), `:1796` ("rendering preview…" during export), `:1118` (`setBuildError(String(err))`). Impact: med. Effort: M. Why: users cancel after the first dialog and ship one plate of the pair the printer needs, read a multi-second export as a preview glitch, and get "Error: …" with no next step. Fix: ask once for a folder/base name and write both files (or label the dialogs "1 of 2 — Artwork" / "2 of 2 — Mask"), key the overlay to the running export ("Building PDFs…"), and route errors through `errMsg` prefixed with the failed action. Lenses: ux (three findings).
10. **Non-fatal load notes render in the destructive red `HeaderAlert` with no dismiss** — `src/App.tsx:1293` (`setLoadError("Note: " + warnings)`). Impact: med. Effort: S. Why: converter warnings and "value(s) benched" notes look like failures and stay red in the header until the next open/save. Fix: a non-destructive Alert variant with a close button for warnings, cleared on the next edit — consistent with conventions.md §Error handling (shadcn Alert via app state). Lenses: ux.
