# Label Lab state machines

Source map for the browser editor, Tauri desktop runtime and headless generator, reviewed at `e8955e98` plus the recovery fix below. Use it to find **who decides what happens next**, not as another specification to maintain in parallel with the code. The last column gives the stem of a nearby suite in `tests/` (or a Rust test module); those are navigation pointers, not a claim that every edge has been tested.

A workflow is implicit here when the same event has a different outcome depending on an earlier event, and that rule lives across callbacks, refs, timers, stored records or resource ownership. Rows group related lifecycles; e.g. each image well is not a new machine. Named models such as `TabsState`, `Selection`, `Stacks` and updater `Status` are called out where they already make part of a workflow explicit. Library-internal widget/OS behavior, build and release automation, and independent display toggles aren't application workflows.

**Within a single call:** there are also stateful readers/writers, not UI lifecycles. `description.ts` tracks first-line header eligibility and open bold/white spans; `logo.ts` pushes/pops SVG group transforms; `pdf/outline.ts` and `psd/build.ts` track current contour and path closure; PDF/canvas drawing scopes graphics state. Preserve their input/output and round-trip tests (`core`, `logo`, `pdf-outline`, `psd-build`, `canvas-draw`). In contrast, resolving layers, checking barcode values, computing placements and planning a display list are derived computations. They don't need lifecycle enums.

## Decision: queued is not committed

The recovery regression is observable in the restored file, not just in an internal flag. With artwork A already stored, queue a snapshot with artwork B, then a text edit reusing B. Refuse the first write and allow the second. Previously the second snapshot reported success and restored the new text **with A**. With no previous art record it could instead be withheld entirely. `keepRecovery` now checks the committed art identity on its turn in the write queue and advances that identity only after IndexedDB reports success. The next pending edit therefore writes B if needed. Repeated edits still skip already stored artwork. No format migration or extra UI.

When changing one of these workflows, start with its owner and the observable terminal outcome: which document, artwork, file, prompt or focused control survives? For an async change, exercise the ordinary path **and the competing event while the first is pending**. Keep independent facts independent: *saved label* is not *saved master*; *hidden warning* is not *dismissed warning*; *bytes posted* are not *bytes still available for retry*. A single global `busy` or `status` would erase precisely these distinctions.
