## Layout

- **Menubar.** File, Edit, View. In the browser it lives in the window. On desktop those same actions sit in the native menu (macOS menu bar, window menu everywhere else), checkmarks and disabled states included, so the in-window copy goes away.
- **Tabs.** One tab per open project, under the menubar. Own undo, own dirty state, own save target.
- **Layers sidebar.** Master picker plus the list. Collapse it from the header.
- **Preview.** The sheet, the mask reveal, or the 3D can. Status bar underneath: zoom, trim size, DPI, view.
- **Inspector.** Right-hand sheet, open while a layer is selected. Not a modal. You can still click the list and the preview.

**Settings** (bleed, DPI, corner radius, appearance) and your colour swatches stick around on this machine. They do not ride in the `.label` file.

## Tabs

**File → New Tab** (`⌘N`) opens another untitled. **Open Project…** (`⌘O`) loads a `.label` into the current tab if you haven't touched it, otherwise a new one.

**Close Tab** (`⌘W`) asks Save / Discard / Cancel when that tab has real work on it. Closing the window walks every dirty tab through the same prompt. The browser build uses the generic leave-page warning instead.

Background tabs keep state and assets. They drop the rendered preview. Switch back and it rebuilds like usual.

A fresh Untitled tab starts "dirty" so Save is live, and it closes without a fuss if you never edited it.

## Command palette

`⌘K` / `Ctrl+K`. Same moves as the menus: new, open, save, export, undo, views, rulers, guides, settings, new variant.

## When something's wrong

Errors land in the header next to the menus. Export greys out while the label is invalid, and the reason sits right there. A rebuild in flight blurs the stale preview so you don't trust it.
