## Layout

- **Menubar.** File, Edit, View. In the browser it lives in the window, and the tab icon is the desktop app icon. Every row carries an icon: the Mac menu shows Apple's standard symbols (they follow light and dark mode), and the browser draws the closest match. On desktop those actions sit in the native menu (macOS menu bar, window menu everywhere else), checkmarks and disabled states included, so the in-window copy goes away.
- **Tabs.** One tab per open project, under the menubar. Own undo, own dirty state, own save target.
- **Layers sidebar.** Master picker plus the list. Collapse it from the header or with `⌘B`.
- **Preview.** The sheet, the mask reveal, or the 3D can. Status bar underneath: zoom, trim size, DPI, view.
- **Inspector.** Right-hand sheet, open while a layer is selected. Not a modal. You can still click the list and the preview.

**Settings** (bleed, DPI, corner radius, appearance) and your colour swatches stick around on this machine. They do not ride in the `.label` file.

## Tabs

**File → New Tab** (`⌘N`) opens an untitled canvas on the last master you applied (layers and positions only — not the previous beer's fills or art). **Open Project…** (`⌘O`) loads a `.label` into the current tab if it is an untitled tab you haven't touched, otherwise a new one. A file you opened stays put, even unedited.

In the desktop app, **File → Open Recent** lists the last ten `.label` files you opened or saved to a new file (Save As, or the first Save), newest first, by file name (a folder name is added when two files share a name). Choosing one opens it just like double-clicking it in Finder. A file that has since moved or been deleted shows an error in the tab strip and drops off the list. **Clear Menu** empties the list. The list is kept on this machine, like Settings.

**Close Tab** (`⌘W`), or the × on a tab, asks Save / Discard / Cancel when that tab has real work on it. Unsaved master edits (a layer added, removed, or reordered in the template) count too, even after the label itself is saved. The prompt's Save writes only the `.label`, so the prompt names those edits: they are discarded when the tab closes unless you choose Cancel and use **File → Save Master** first. Closing the window or quitting walks every dirty tab through the same prompt: `⌘Q`, and on macOS also Dock → Quit, logging out, or shutting down (Label Lab stops the logout until you've decided; if the prompt does not appear, choosing Quit again within a few seconds quits anyway). On Windows, logging out or shutting down closes Label Lab without the prompt, so unsaved work is only kept by the recovery snapshot. The browser build uses the generic leave-page warning instead.

The active tab shows its × dimmed at all times; other tabs show theirs on hover. A tab with unsaved changes shows a • in that spot instead, which is also its close button.

Background tabs keep state and assets. They drop the rendered preview. Switch back and it rebuilds like usual.

A fresh Untitled tab starts "dirty" so Save is live, and it closes without a fuss if you never edited it.

Tabs with unsaved changes keep a recovery copy as you work. If Label Lab crashes or is forced to quit, the next launch offers them back: **Restore** reopens each one as an unsaved tab, **Discard** throws the copies away. On the desktop app, a restored tab that came from a `.label` saves back to that file, as long as the file is still there, hasn't been saved since the copy was taken, and isn't open in another tab. Otherwise Save asks where to write it, and a note names the original file. Closing the offer without choosing keeps them for next time. Changes from the last couple of seconds before a crash may be missing.

## Command palette

`⌘K` / `Ctrl+K`. Same moves as the menus (new, open, save, export, undo, views, rulers, guides, zoom, settings; the Rulers and Guides items read Show/Hide rulers and Show/Hide guides), plus New Variant, Add Text / Image / Barcode / QR Layer and Remove Layer, which are not in the menus.

## When something's wrong

Errors land in the header next to the menus. Export greys out while the label is invalid, and the reason sits right there: click it to select the first invalid layer. An export in flight blurs the preview under a **Building PDFs…** or **Building PSDs…** note.

A failure that escapes all of that (a save, export or open that breaks somewhere unexpected) shows a **Something went wrong** alert at the bottom of the window with the reason. Your tabs are untouched, but check that the last action actually finished before relying on it. **Dismiss** clears it.
