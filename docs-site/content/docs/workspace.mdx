## Layout

- **Menubar.** File, Edit, Layer, View. In the browser it lives in the window, and the tab icon is the desktop app icon. Every row carries an icon: the Mac menu shows Apple's standard symbols (they follow light and dark mode), and the browser draws the closest match. On desktop those actions sit in the native menu (macOS menu bar, window menu everywhere else), checkmarks and disabled states included, so the in-window copy goes away.
- **Tabs.** One tab per open label, under the menubar. Own undo, own dirty state, own save target.
- **Layers sidebar.** Master picker plus the list. Collapse it from the header button, View → Layers, or `⌘B`.
- **Preview.** The sheet, the mask reveal, the flat rendered label, or the 3D can. Status bar underneath: zoom and the Label | Mask | Rendered | Can view control.
- **Inspector.** Right-hand sheet, open while a layer is selected. Not a modal. You can still click the list and the preview.

**Settings** (bleed, PSD resolution, corner radius) and the View → Appearance theme, plus your colour swatches, stick around on this machine. They do not ride in the `.label` file.

## Tabs

**File → New Tab** (`⌘N`) opens an untitled canvas on the last master you applied (layers and positions only — not the previous beer's fills or art). **Open Label…** (`⌘O`) loads a `.label` into the current tab if it is an untitled tab you haven't touched, otherwise a new one. A file you opened stays put, even unedited.

In the desktop app, **File → Open Recent** lists the last ten `.label` files you opened or saved to a new file (Save As, or the first Save), newest first, by file name (a folder name is added when two files share a name). Choosing one opens it just like double-clicking it in Finder. A file that has since moved or been deleted shows a **Could not open label** error toast and drops off the list. **Clear Menu** empties the list. The list is kept on this machine, like Settings.

**Close Tab** (`⌘W`), or the × on a tab, asks Save / Discard / Cancel when that tab has real work on it. Unsaved master edits (a layer added, removed, or reordered in the template) count too, even after the label itself is saved. The prompt's Save keeps both: when the master has unsaved edits it saves the master first, exactly as **File → Save Master…** does (straight to the file, or the review when the label has overrides to promote), then the `.label`, and closes the tab. Cancel the review or a save dialog (or a failed save) and the tab stays open. When you are quitting, that also stops the quit. Closing the window or quitting walks every dirty tab through the same prompt, worded for quitting (Cancel keeps Label Lab open). With more than one dirty tab you're asked once first: **Review Changes…** walks them one prompt at a time, **Discard All** quits without saving any, **Cancel** keeps Label Lab open. That applies to `⌘Q`, and on macOS also Dock → Quit, logging out, or shutting down (Label Lab stops the logout until you've decided; if the prompt does not appear, choosing Quit again within a few seconds quits anyway). On Windows, logging out or shutting down closes Label Lab without the prompt, so unsaved work is only kept by the recovery snapshot. The browser build uses the generic leave-page warning instead.

The active tab shows its × dimmed at all times; other tabs show theirs on hover. A tab with unsaved changes shows a • in that spot instead, which is also its close button.

Background tabs keep state and assets. They drop the rendered preview. Switch back and it rebuilds like usual.

A fresh Untitled tab starts "dirty" so Save is live, and it closes without a fuss if you never edited it.

Tabs with unsaved changes keep a recovery copy as you work. If Label Lab crashes or is forced to quit, the next launch offers them back: **Restore** reopens each one as an unsaved tab, **Discard** throws the copies away. On the desktop app, a restored tab that came from a `.label` saves back to that file, as long as the file is still there, hasn't been changed since that tab last opened or saved it, and isn't open in another tab. Otherwise Save asks where to write it, and a warning toast names the original file. Closing the offer without choosing keeps them for next time. Changes from the last couple of seconds before a crash may be missing.

## Command palette

`⌘K` / `Ctrl+K`. Every menu command, grouped and named as the menus show them (File, Export, Edit, Layer, View, Units, Appearance). A view or toggle that is on shows a check mark, as in the menu. **New Variant**, which is in no menu, is listed last under Other. Type a menu name to narrow it down: "view label" finds the Label view, "appearance dark" the dark theme.

## When something's wrong

The header carries no messages. They appear as toasts at the bottom of the preview. An invalid value also shows where it is: its layer's row in the Layers list turns red and gives the reason. Up to four toasts show at once, each in full; with a fifth, the oldest is hidden until a newer one closes.

Messages about something that is still wrong belong to their tab. They show while that tab is in front, hide when you switch away, and come back when you return. They are art that won't load (a texture, a mask or an image), fonts or art the preview can't assemble, a preview that won't draw, and the warning when a label refers to something its master doesn't have (a layer it overrides, a variant, or a layer a barcode or QR value names). Each stays until what caused it is fixed or you close it. A bad texture or mask clears when you drop a good one, a bad image when you drop a good one into any image field, a preview error when a frame draws fine, and a font or art the preview can't assemble the next time it assembles: picking a font that loads, or hiding the plate that holds the broken art, can fix it. Saving clears none of them. A message you closed stays closed until its cause raises it again: another failed drop, a different preview error or label warning, or the preview failing to assemble once more, which shows its message again even when the text is the same.

Messages about something that just happened show whichever tab is in front: export results (see [Export](/docs/export)), the **Saved …** after Save Master, the warning when opening a label or master sets values aside (its title names the file, and it goes when you close that tab), a failure to open or save a label or master (including a recent file that is gone, or a file opened from Finder that isn't a `.label`), an edit that was refused, and a menu error on the desktop app. A failure stays until you close it, and a repeat replaces it rather than stacking another. The one exception is a failed label Save, which also goes when the next Save works. Choosing Export while the label is invalid shows a **Can't export yet** toast with the reason and a **Show layer** button (see [Export](/docs/export)); that toast belongs to its tab and goes when the label is valid again. An export in flight blurs the preview under a **Building PDFs…** or **Building PSDs…** note.

A failure that escapes all of that (a save, export or open that breaks somewhere unexpected) shows a **Something went wrong** toast with the reason. Your tabs are untouched, but check that the last action actually finished before relying on it. It stays until you close it, and a newer failure replaces it rather than stacking another.
