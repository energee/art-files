---
title: Headless generate
description: PDFs and PSDs from a master and JSON, no window
---

Same resolve, plan, and build path as the app. No window. The CLI uses the master’s bleed and 600-DPI PSD output; it does not read the app’s local Settings. WebP assets must be converted to PNG/JPEG first.

```bash
npm run generate -- beer.master values.json ./out
# writes {name}.pdf (art + White Ink spot), {name}.psd, {name}-mask.psd

npm run -s generate -- beer.master --inspect
# prints the master's layer ids (the keys values.json uses)
```

`values.json` is keyed by layer id (`name`, `abv`, `description`, `barcode`, …). Text layers take a string. Rich layers still understand the markdown subset: `# header`, `**bold**`, `_white ink_`. A JSON array is a batch, one output set per job. A job can also be `{values, variants, files, overrides}`. `overrides` patches layer fields and is type-checked against the layer before anything builds. Colours there, and in styled lines, take 3- or 6-digit hex (`#fff` reads as `#ffffff`) or `none`; a named colour such as `gold` is an error. A batch is validated, read, and built whole before the first file is written. A bad job anywhere leaves nothing on disk.

```bash
npm run generate -- beer.master values.json ./out --variant collab \
  --asset collabLeft=./logo.svg --format pdf

npm run generate -- --master beer.master --values - --out ./out   # stdin
npm run generate -- --master beer.master --label run.label --out ./out
npm run generate -- beer.master values.json ./out --set name=X
```

- `--variant id`: enable a variant (union with variants already on a `--label`)
- `--asset layerId=path`: attach an image file. `--asset background=` / `mask=` need a master with that role layer
- `--format pdf` or `psd`: emit only the print PDF or only the PSD pair. Default emits both formats
- `--two-file`: emit the legacy artwork PDF and blue/white mask PDF instead of the combined print PDF. Works with master, batch, label and legacy inputs; PSD output is unchanged. A later run without `--two-file` into the same folder warns on stderr if the older `{name}-mask.pdf` is still there; it is never deleted.
- `--set id=value`: overlay one value on every job
- `--inspect`: JSON on stdout, exit 0. Use `npm run -s` when piping output so npm does not add its banner
- `--check`: validate every job and print its errors and warnings, then stop. Nothing is built or written, so no output directory is needed (one given is ignored). Exit 0 when every job passes

`--check` catches what a full run would reject: unknown layer ids, bad values and overrides, invalid barcodes, missing image files, two jobs writing the same file, and characters the layer's font has no glyph for (they would print as empty boxes, so export refuses them). It does not decode images, so a corrupt or unsupported image file still fails only in the full run.

```bash
npm run generate -- beer.master batch.json --check
```

A spreadsheet becomes a batch with any CSV-to-JSON tool. Name the columns after layer ids, export CSV, then, for example:

```bash
npx csvtojson batch.csv > batch.json
```

Relative paths resolve against the directory you run `npm run generate` from, even though npm runs the script from the repo root.

Exit codes: **0** wrote everything (with `--check`: every job is valid), **1** a job or input was rejected, **2** bad argv.

The older texture/mask/config.json argv still works for golden re-baselines:

```bash
npm run generate -- <texture|none> <mask.png|none> <outDir> [config.json] [--two-file]
```
