Same editor, two shells: a local web app, and **Label Lab** on macOS, Windows, and Linux.

## Browser

From the repo root, with Node.js 24 (the version in `.nvmrc`, so `nvm use` picks it):

```bash
npm install
npm run dev
```

Open the URL Vite prints, always http://localhost:5173. If something else already holds that port, Vite stops with an error instead of moving to another one, because the desktop window only looks at 5173. Run a second browser-only copy with `npx vite --port 5174`.

The label is already on screen, type on bare stock, until you drop a texture. Type and the preview keeps up.

## Desktop (Label Lab)

Same UI, native menus, real open/save dialogs, and double-click for `.label` files.

A development window wants Node.js 24 (see `.nvmrc`) plus a stable Rust toolchain. On macOS: `xcode-select --install`. On Linux: the WebKitGTK dev packages.

```bash
rustup toolchain install stable
npm run desktop:dev
```

`npm run desktop:build` drops the installer in `src-tauri/target/release/bundle/`. macOS gets a `.app` and a DMG, Windows an NSIS `setup.exe`, Linux an AppImage (Debian 13 "trixie" and newer). Local Mac builds are ad-hoc signed. Shipping to other Macs without Gatekeeper yelling means Apple signing and notarization, and Windows needs a signed installer to get past SmartScreen. The release workflow does both once its signing secrets are set (see the signing steps in `.github/workflows/release.yml`). Until then, published Mac builds are ad-hoc signed and Windows builds unsigned.

Double-click a `.label` and it opens in Label Lab, even if the app is already running: the window comes to the front, even from minimized. New tab, or it focuses the tab that already has that file. On Linux the association shows up once the AppImage is desktop-integrated. `Label_Lab.AppImage path/to/file.label` works either way.

Published builds check the configured update feed after launch and when the window comes back. On macOS, **Label Lab → Check for Updates…** requests a check on demand. On Windows and Linux, use **Help → Check for Updates…**. An update found by an automatic check appears in the status bar; when you're already up to date the status bar stays empty, and only a check you asked for says so. **Restart Now** (or **Install and Restart** on Windows) first walks any unsaved tabs the way quitting does, and Cancel there keeps Label Lab running. If an install fails, **Try again** installs the same update again. Development builds do not receive automatic updates.

## Your first document

An untitled tab brings back the last master you applied (File → Open Master…, Save Master…, or the picker) — the layers and their positions, not that beer's name or art. Never applied one? You get the shipped Lolev template.

Give it five minutes:

1. Check the master at the top of the left sidebar.
2. Drop a rock texture on the window (PNG, JPEG, or WebP). While you drag, the preview splits into two drop zones: left for the background, right for the metallic mask. Optional: drop a metallic mask (PNG or WebP) on the right half.
3. Click **Name** in the Layers list and type this beer.
4. ABV, UPC, description, the rest, from the inspector.
5. File → Export → Export PDF once the label is valid. The print file contains the artwork and a White Ink spot layer; inspect it in Acrobat with Overprint Preview enabled.
