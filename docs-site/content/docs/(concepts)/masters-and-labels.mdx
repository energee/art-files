title: Masters and labels
description: What the master and the label each hold, the master picker, and Save Master.

Two files, on purpose.

| File | What it is |
| --- | --- |
| **Master** (`.master`) | The brand. Size, background, mask, every layer, guides, named variants. Shared by every beer that wears this look. |
| **Label** (`.label`) | This release. Which master, which variants are on, the filled values, and any overrides for this beer only. |

What you see is the resolved label: master layers, plus enabled variant diffs, plus this beer's fills and overrides.

## What writes where

- **Fills** (name, ABV, UPC, logos you drop) belong to the label.
- **Property edits** (move, resize, colour, type) also belong to the label, as overrides. They do not rewrite the template until you promote them.
- **Structure** (add, remove, reorder, rename a layer; new variant; guides; master name) writes the master in this session, and shows up when you save the master.
- **Fill contract** (field label, placeholder, choices, number suffix, barcode symbology on a text-as-code field) is template vocabulary. Master.

You can fill beers all day without drifting the brand. File → Save Master… is the gate.

## Master picker

Top of the left sidebar. It shows which master and version this label uses, and where Save Master promotions go.

- This label's master comes first, then its **variants as versions**, with a check mark on the one you're editing. Switch a version and a later Save Master or promotion lands in that variant, not the base master.
- **Other masters** lists the rest of the library. When two masters share a name, each shows its file name and the day it was last used on this computer. The built-in Starter master reads **Built in**; a master opened in the browser reads **No file**.
- **New Variant** sits at the foot of the menu (also in the `⌘K` palette).
- **Save Master…** appears at the end of the picker's row while the master itself has unsaved changes, such as a layer added, removed or reordered. It reads **Save Variant…** while a variant is the version.

Moving, restyling or filling a layer is a label override that `⌘S` saves; it doesn't bring up Save Master. To promote overrides into the master, use File → Save Master…, which stays enabled while the label has any.

### Switching masters

Picking another master switches this label to it at once:

- Filled fields or variants the new master can't show move to the bench.
- A **Switched to “…”** toast names them and offers **Undo**. Undo, or `⌘Z`, puts the label back on its old master with everything it had.
- Art the switch filled into an empty texture, mask or image slot stays after Undo. Clear it by hand if you don't want it.

### Removing a master from the library

The **×** on a master's row, or Delete on the highlighted row, removes it from the library on this computer. The `.master` file stays where it is, and **Undo** puts it back. A remembered master whose file has been deleted, with no saved copy, is dropped from the library when you pick it.

## Save Master

File → **Save Master…** (or **Save Master As…**) writes the template. When this label has nothing to promote, it writes straight away (Save Master As goes straight to the save dialog), and a toast says **Saved lolev.master** with *3 changes* under it. An image the master can't carry (the label names it, but its file is missing) gets a warning toast of its own.

When the label has overrides or filled values that could go into the master, a review opens first:

- Structural rows (added, removed, reordered, renamed), as a plain list: they are already in the master. Moving one layer lists that layer alone, not every layer it passed
- Fill-contract edits, listed the same way
- This label's overrides and values, each with a tick, so you can **promote** them into the master (or the version the picker names)

One tick can promote everything. Confirm, and the `.master` file writes. Save Master As mints a new master id, rebinds this document onto it, and writes the new file.

Save Master writes back to the file this master was opened from or last saved to. Undo back past Open Master, a library pick, or Save Master As, and Save Master asks where to save instead of reusing the other master's file.

File → **Open Master…** loads a template from disk and adds it to the library. It also switches this label to it at once, like picking it in the master picker, with the same toast and the same Undo and ⌘Z. Save Master then writes to the opened file. The desktop app remembers the real path, so a restart finds it. The browser keeps copies of the 20 masters you most recently opened, saved or used, so a reload does not sneak you back to shipped Lolev. A master you haven't touched in 20 others is dropped from the browser; open its file again to bring it back. A browser can also clear what a site has stored, for example after some days without a visit, and the library goes with it. Keep your `.master` files. Where the browser has no save dialog, Save Master downloads the master.

Opening a label reads that master file. If the file was saved again over the same path (Save Master As writes a new id), the label follows the file. It does not reopen an older copy remembered from the id the label still names. Saving the label records the new id.

<Callout title="Untitled tabs">
  A new tab reopens the last master you applied — which layers exist and where they sit. Fillable text (name, style, ABV, and the like) and the beer's background, mask and Collab logos stay off; those belong to a `.label`. Template copy such as the wordmark, and images placed in the master such as a script logo, stay. The built-in Starter master is the fallback when you have never applied a master. A label saved on a master this computer has no file for asks you to locate its `.master` once.
</Callout>
